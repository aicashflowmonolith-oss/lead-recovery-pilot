Output you can actually use

Valid

Target mailbox is explicitly accepted while a random mailbox is rejected.

Risky

Catch-all, role account, disposable domain, or another material risk flag.

Invalid

Malformed address, no mail route, or explicit hard mailbox rejection.

Unknown

Greylisting, gateway policy, unreachable SMTP, or ambiguous evidence. Unknown is never promoted to valid.

What gets checked

Syntax + domain

Normalizes the address and rejects malformed inputs before network probing.

DNS / MX

Confirms the domain has a usable mail route.

SMTP mailbox probe

Checks recipient response without sending a message body.

Catch-all + risk signals

Uses a random-recipient probe plus role/disposable-domain flags.

Evidence-first by design. SMTP verification is not perfect: some providers intentionally hide mailbox state. MONOLITH reports uncertainty instead of inventing certainty. High-volume deployment is scoped to the customer's volume, hosting constraints, and acceptable-use requirements before production use.
